## Concrete draft choices

The sources delegate wire representation. These are proposed choices, not claims that existing sources already fixed these spellings:

- Root tag: `ofarm.protectedEffectValidationTrace.v0.1`; schema ID: `https://ofarm.dev/schema/drafts/non-default/authorization-finalization-evidence/protected-effect-validation-trace/v0.1`.
- `validationTraceId` is a nonempty opaque immutable identity. It is not a computed digest and is allocated before the trace is finalized. Exact strings are preserved. The authoritative producer/resolver must enforce one ID to one immutable value; a local fixture registry can test collisions but does not prove global uniqueness.
- The root binds one `actionClass`, authorization result `{ref,digest}`, `decisionBundleDigest`, selected full action-rule binding, exact effect intent and its schema, one proposed result ID/ref/digest/schema, exact protected-effect contract, explicit selected action/body-schema binding, external domain payload, and overall disposition. `actionClass` is carried, not admitted by this schema. The selected release action set does not change. Multiple result composition is outside this v0.1 profile and cannot be inferred from a list or a second hidden result.
- `selectedActionBodySchemaBinding` is a required root sibling of `protectedEffectContractBinding`, not a fifth member of the PR40-compatible contract object. It carries the exact selected body schema ref (including its fragment), version, document-byte digest and canonicalization tag. `actionClass` already names the selected action; the independent owner context and resolved contract must agree on the same action/body selection. In the explicitly fictional single-body fixture, the comparison target is `contract["value"]["bodySchemaBinding"]`. A real multi-action contract needs its owner-defined action-specific selector; the shared verifier does not infer a branch from a type name, choose a body by position, or create a mapping rule.
- The selected rule's complete revision selector is exactly one of `revisionRef` or `contentDigest`, using the PR40 shape. Do not drop a selector, replace a revision selector with a digest selector, choose latest, normalize strings or infer equality by family name.
- `schemaBinding` uses PR40's four names: `schemaRef`, `schemaVersion`, `schemaDigest`, `canonicalization`. Here `schemaDigest` means `sha256:` plus SHA-256 of the exact UTF-8 schema document bytes. A full `schemaRef`, including any fragment, selects a pinned schema location within that document; its digest still covers the entire document. `canonicalization = JCS_RFC8785_SHA256` describes the value convention, not canonicalization of the schema file before byte hashing. The registry must bind the version and full selector explicitly; a `$id` alone is insufficient.
- The domain payload is external, not an unconstrained inline JSON object. `domainPayload` contains only `ref`, `digest`, `schemaBinding` and `overallDispositionPointer`. Its required exact pointer is `/overallDisposition`. A future domain payload schema must expose PASS/FAIL at that member. The resolved selected target must declare `type: object` and `additionalProperties: false`; that admission check neither prohibits names admitted by `patternProperties` nor establishes recursive restrictions on nested objects. Nested restrictions remain with the selected schema's owner. This is the proposed interface convention; it neither defines how the verdict is reached nor materializes the missing AssertionRecord payload. It also requires the four fixed subject fields below inside the actual hashed payload for both PASS and FAIL. The selected payload schema must explicitly declare these properties and mark them required; existing shared digest and schema-binding value checks enforce their types and complete values without requiring byte-identical schema fragments. Missing values fail, and verification never synthesizes them from the trace. No configurable subject pointer or trace-root field is added. Other owner layouts require an explicit compatible interface amendment, not an inferred fallback pointer.
- `overallDisposition` is copied from that exact payload member and is only PASS or FAIL. Per-check NOT_APPLICABLE and NOT_EVALUATED remain inside the separately owned payload and cannot become overall outcomes. The shared verifier checks exact verdict equality, not whether a FAIL should have been PASS or whether evaluations really ran.
- Whole trace content is addressed externally as `urn:ofarm:protected-effect-validation-trace:sha256:` followed by the 64 lowercase hash digits. The accompanying `digest` is `sha256:` followed by those same digits. No trace reference, self-digest, provisional sentinel or future record link is a root member. The auxiliary `$defs/traceReference` is not a second root record type.

The four fixed payload subject bindings are:

| Actual payload pointer | Exact verified trace comparison |
| --- | --- |
| `/proposedResultDigest` | `/proposedResult/resultDigest` |
| `/effectIntentDigest` | `/effectIntent/digest` |
| `/protectedEffectContractDigest` | `/protectedEffectContractBinding/contractDigest` |
| `/selectedActionBodySchemaBinding` | Complete `/selectedActionBodySchemaBinding`: selector/fragment, version, schema-file digest and canonicalization |

These duplicate only already-bound subjects inside the separately hashed payload.
They establish declared-subject agreement, not truthful evaluation. A producer
can relabel all four fields and recompute hashes. `AR_EFFECT_SUBJECT`, `AR_ID`,
`AR_BODY`, domain prerequisites and production payload adoption remain with PR23.

## Strict bytes and acyclic construction

Pin RFC 8785 JCS, UTF-8 and SHA-256. The existing component environment uses Python `rfc8785==0.1.4`; any independent implementation must produce identical JCS bytes, not substitute ordinary `json.dumps(sort_keys=True)`. Verify the checker records its actual library version. Exact schema-file SHA-256 is a separate operation from a value's JCS digest.

1. Strictly decode UTF-8 JSON before obtaining an object model. Reject duplicate names at every depth, BOM, malformed JSON, trailing content, non-finite numbers and lone Unicode surrogates. Reject integers outside the interoperable safe range `[-9007199254740991, 9007199254740991]`; reject numeric values that the pinned RFC 8785 implementation cannot represent. Do not silently truncate or stringify numbers. JCS's prescribed number serialization is allowed; do not add Unicode, timestamp, case, ref, selector or version normalization.
2. Resolve the selected owner binding context independently of the trace. It supplies the exact expected action, authorization result/decision bundle, full rule selector and digest, intent/schema, result ID/ref/digest/schema, contract, selected action/body-schema binding and domain-payload schema binding. Self-declared trace bindings are never their own expected context. The harness receives fixed fictional expected context as separate input; it does not exercise a real independent context producer. No runtime producer of this context is supplied by this component.
3. Resolve and verify real locally pinned schema documents and every referenced schema dependency. Match exact bytes/digests, version and complete selector. Validate the schema document under Draft 2020-12 and require its resolved selected target to declare `type: object` and `additionalProperties: false`. This does not prohibit names admitted by `patternProperties` or establish recursive closure of nested objects; nested restrictions, including objects in arrays, remain owner-defined. Validation still applies all constraints present in the selected schema. The complete pinned schema/reference dependency set concerns where references resolve, separately from object-property restrictions. No network, wildcard, fallback, boolean-true schema, unbound dynamic schema or merely plausible digest is an acceptable replacement. Unavailable, mismatched or unreviewed schemas stop integrity verification, for FAIL as well as PASS traces.
4. Finalize the foreign authorization result, rule, effect intent, proposed result and protected-effect contract under their respective owner rules. The trace carries their exact bindings. For example, PR23 resultDigest covers JCS of the whole result with no exclusions; its contractDigest removes exactly the contract's own top-level member. PR11 decisionBundleDigest retains PR11's joint projection. Do not use the trace's whole-value rule to guess any other owner's digest. Missing real foreign bytes/projection/binding remain an unavailable dependency, not a successful verification.
5. Produce the domain-owned payload against its real selected schema, with the target admission checks from step 3. Require its explicit subject-property and required-field declarations, populate the four subject fields from finalized owner inputs during payload production, and validate the complete payload value. Verification independently reads and compares the actual fields; it never inserts or repairs them. The protected-effect contract binds the payload schema, not a future concrete payload digest. Then compute `domainPayload.digest = sha256: + SHA256(JCS(payload))`, excluding nothing. The payload must not depend on a future trace/receipt/consumption/attempt digest. Its owner retains all AR/PC applicability, prerequisite, verdict and truthful-execution obligations. The proposed shared payload hash convention requires the domain payload to be self-digest-free; do not apply a foreign self-digest exclusion to it.
6. Assemble and validate the closed trace value with every binding fixed. Require the resolved payload's `/overallDisposition` to equal the trace's disposition exactly. For both PASS and FAIL, compare its actual four subject fields to the verified trace members in the table above: exact digest strings and complete body-binding equality are required even after honest rehashing. Compare each complete carried binding with its separately supplied expectation. Compare `selectedActionBodySchemaBinding` with the complete body binding selected by the resolved contract for the same action, including ref/fragment, version, file-byte digest and canonicalization. Retain full-result schema validation and apply the already resolved selected-body validator to `result.value.assertionBody`. Both conformance and the binding comparisons are required even if a producer honestly recomputes every affected hash. The exact checklist and owner gaps are below; the actual-body check is implemented alongside the existing comparisons. There is no generic identity-continuity claim. The root `authorizationResult.digest` is an owner-defined record digest and is not automatically equal to `decisionBundleDigest`.
7. Compute `H = lowercase_hex(SHA256(JCS(complete trace value)))`. Excluded JSON Pointers: **none**. Construct the external reference `{ref: "urn:ofarm:protected-effect-validation-trace:sha256:" + H, digest: "sha256:" + H}`. Verify both strings against actual trace bytes. That reference carries the trace into PR40; it is not inserted into the trace. No original raw formatting claim is made for JCS-addressed values: lexical whitespace or key order can differ with the same JCS value, while exact string/array-value changes must be preserved and hashed.
8. Freeze the trace. Later consumption, attempt and receipt records may bind the finalized trace ref/digest under PR26's existing ordering. The payload is finalized before the trace; the trace before those later records. This component adds no backward digest edge, no future timestamp and no proof of commit. Changed bytes cannot reuse an existing immutable trace ID or ref/digest. That restriction is necessary for record integrity but is not permission to issue or consume a replacement PASS under a new ID for the same attempt or subject. The envelope has no explicit attempt-ID field or authoritative attempt-history comparison. Its authorization-result binding supplies attempt-linkage material under the owner's non-reuse rules, but this checker cannot establish whether a second trace is admissible. Keep earlier FAIL evidence unchanged and retain the separate PR26 failure/admission obligations tracked by B1.

   For the current trace resolved from an authoritative attempt's `protectedEffectValidation.trace`, the consumer must require the complete `trace.authorizationResult` binding (ref and digest) to equal `attempt.authorizationBundle.result`, and `trace.decisionBundleDigest` to equal `attempt.authorizationBundle.decisionBundleDigest`. Verify the trace reference/digest and owner-defined authorization bytes/projections; the authorization-result record digest is not the decision-bundle digest. A trace retained inside a prior admitted-result binding remains provenance for that original attempt and must not substitute for the current attempt's fresh validation trace. This envelope checker supplies no authoritative attempt producer, transaction-history lookup or consumption enforcement.

## Checks beyond JSON Schema

JSON Schema enforces the root and all common binding object members, including the required selected action/body-schema object, exact profile/canonicalization constants, selector exclusivity, digest lexical form, whole closed payload binding, fixed verdict pointer and PASS/FAIL carriage. Every reusable object definition is closed. The external reference shape is separately validateable through `$defs/traceReference`.

The component checker must separately exercise duplicate-name rejection, JCS validity/canonicalization, exact expected-binding equality including the selected body binding, selected-body equality with the resolved contract, actual body conformance under the resolved selected schema alongside complete-result validation, content-digest selector agreement with the resolved rule, pinned local schema/reference dependency resolution, the selected target's `type: object` and `additionalProperties: false` declarations, explicit payload subject-property and required-field declarations, payload schema validation, exact actual payload-subject comparisons for PASS and FAIL, payload digest and verdict equality, external trace reference/hash equality, and local immutable-ID collision rejection. With PR40's unchanged schema it must verify both the external record binding and the trace/disposition wrapper. Each binding comparison includes the entire selected object, full selectors and exact strings, not only the hash token. The earlier selected-body correction has separately targeted omission/shape, expected-context drift, resolved-contract disagreement and whole-value digest controls. The added F4 counterexample makes the trace, expected context and fictional contract all select `structureAssertionBody`, with all affected hashes honestly recomputed, while the actual operation-claim body does not conform despite a valid complete result. The committed `selected_body_agreement_rejects_nonconforming_actual_result_body` case requires rejection at `resultBody` with the root `additionalProperties` witness. The 265 controls inherited from `9185519` preserve their purposes, order, outcomes and 103 exact schema witnesses through required payload-field and digest rebasing, apart from the precise identity-only case rename. New committed controls cover retained R1 payload versus valid R2 under honest re-finalization, isolated intent/contract/body mismatches, missing/malformed fields and matching PASS/FAIL subjects. The fixture contains 307 cases (24 positive/283 negative), with 124 exact schema witnesses. Nine `payload-interface` controls edit declaration metadata after real pinned resolution and do not claim a changed document passed its original schema hash. The component manifest records totals; the committed runner and thirteen-check suite supply public verification. These controls do not establish domain execution or transaction enforcement.

A schema-valid trace is **shape-valid only**. Successful envelope integrity verification means its carried bindings, available local bytes and copied verdict agree under this draft. It does not establish that the domain checks ran, that the claimed verdict is true, that trusted state is genuine, that authorization is current, or that a result was admitted/committed. Deliberately fictional schema-bound payload/contract/record examples can verify the envelope mechanism, but must be identified as TEST_ONLY and never reported as a real domain-contract pass. An unavailable foreign dependency must be reported as unavailable, not converted into a fabricated overall FAIL and not counted as verified integrity.

## Open owners and exact missing decisions

1. **Domain owner, PR23 §11.2:** materialize the actual AssertionRecord validation payload schema and its owner-defined nested restrictions, AR/PC applicability/prerequisite graph, selected action/body bindings, resolved evidence comparisons and verdict procedure. Adopt or explicitly amend the proposed fixed `/overallDisposition` and four subject-field interface with self-digest-free payload bytes. Subject equality does not implement `AR_EFFECT_SUBJECT`, `AR_ID` or `AR_BODY`, and no relabelled payload proves those rules were evaluated. This envelope can carry the eventual payload but does not create it.
2. **Domain and authorization binding owners, PR23 §§7.1/11/15 and PR11 §24:** materialize the complete protected-effect contract and all three action/body input bindings, and bind the selected release manifest. Existing operation intent/result bytes are not a complete contract. Structure/compliance remain full-contract dependencies; their action admission is not expanded.
3. **Authorization owner, PR11:** provide actual result/rule/bundle schemas, complete digest projections and independently admitted selected binding context. The envelope does not treat external ref/digest syntax as proof that those records exist.
4. **Domain/source/temporal owners:** F1/F2 qualifier admission, prospective global identity, trusted temporal source selection, prior creation/ingress/snapshot proofs, source-history completeness, twin applicability and all other foreign checks stay open. A full revision selector or matching local digest supplies none of their truth.
5. **Transaction/runtime owners, PR26/issue #25:** enforce the step-8 current-attempt comparisons together with the complete success set, authoritative single-use decision consumption and immutable outcome/history rules (PR26 §§9.2–9.4, 10–13). A failed attempt and its FAIL trace remain non-consumable; a later attempt is allowed only by the recorded consequence and current admission checks, with fresh authorization and a fresh passing trace. Replaying a completed matching operation resolves its original verified result/receipt and creates no new consumption. PR43 does not introduce an independent `(authorizationResult, proposedResult)` trace quota or treat a new trace ID as admission permission. Authoritative attempt resolution, guarded atomicity, status/uniqueness/history persistence and real PR11 authorization projections remain this separate prerequisite. Prior admitted-result provenance stays tied to its original attempt. No actual `PC_TRANSACTION_HANDOFF` evaluation, terminality enforcement or future commit proof is supplied here.

No packaging conflict was found with PR40's existing reference fields. The new payload interface is an explicit draft representation for owner review, not an invented successful production payload. OFARM2 #392/#396 stays parked. No current/default files, earlier manifests or source-owner documents are edited.

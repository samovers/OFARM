## Concrete draft choices

The sources delegate wire representation. These are proposed choices, not claims that existing sources already fixed these spellings:

- Root tag: `ofarm.protectedEffectValidationTrace.v0.1`; schema ID: `https://ofarm.dev/schema/drafts/non-default/authorization-finalization-evidence/protected-effect-validation-trace/v0.1`.
- `validationTraceId` is a nonempty opaque immutable identity. It is not a computed digest and is allocated before the trace is finalized. Exact strings are preserved. The authoritative producer/resolver must enforce one ID to one immutable value; a local fixture registry can test collisions but does not prove global uniqueness.
- The root binds one `actionClass`, authorization result `{ref,digest}`, `decisionBundleDigest`, selected full action-rule binding, exact effect intent and its schema, one proposed result ID/ref/digest/schema, exact protected-effect contract, explicit selected action/body-schema binding, external domain payload, and overall disposition. `actionClass` is carried, not admitted by this schema. The selected release action set does not change. Multiple result composition is outside this v0.1 profile and cannot be inferred from a list or a second hidden result.
- `selectedActionBodySchemaBinding` is a required root sibling of `protectedEffectContractBinding`, not a fifth member of the PR40-compatible contract object. It carries the exact selected body schema ref (including its fragment), version, document-byte digest and canonicalization tag. `actionClass` already names the selected action; the independent owner context and resolved contract must agree on the same action/body selection. In the explicitly fictional single-body fixture, the comparison target is `contract["value"]["bodySchemaBinding"]`. A real multi-action contract needs its owner-defined action-specific selector; the shared verifier does not infer a branch from a type name, choose a body by position, or create a mapping rule.
- The selected rule's complete revision selector is exactly one of `revisionRef` or `contentDigest`, using the PR40 shape. Do not drop a selector, replace a revision selector with a digest selector, choose latest, normalize strings or infer equality by family name.
- `schemaBinding` uses PR40's four names: `schemaRef`, `schemaVersion`, `schemaDigest`, `canonicalization`. Here `schemaDigest` means `sha256:` plus SHA-256 of the exact UTF-8 schema document bytes. A full `schemaRef`, including any fragment, selects a pinned schema location within that document; its digest still covers the entire document. `canonicalization = JCS_RFC8785_SHA256` describes the value convention, not canonicalization of the schema file before byte hashing. The registry must bind the version and full selector explicitly; a `$id` alone is insufficient.
- The domain payload is external, not an unconstrained inline JSON object. `domainPayload` contains only `ref`, `digest`, `schemaBinding` and `overallDispositionPointer`. Its required exact pointer is `/overallDisposition`. A future domain payload schema must be a real closed object schema exposing PASS/FAIL at that member. This is the proposed interface convention; it neither defines how the verdict is reached nor materializes the missing AssertionRecord payload. Other owner layouts require an explicit compatible interface amendment, not an inferred fallback pointer.
- `overallDisposition` is copied from that exact payload member and is only PASS or FAIL. Per-check NOT_APPLICABLE and NOT_EVALUATED remain inside the separately owned payload and cannot become overall outcomes. The shared verifier checks exact verdict equality, not whether a FAIL should have been PASS or whether evaluations really ran.
- Whole trace content is addressed externally as `urn:ofarm:protected-effect-validation-trace:sha256:` followed by the 64 lowercase hash digits. The accompanying `digest` is `sha256:` followed by those same digits. No trace reference, self-digest, provisional sentinel or future record link is a root member. The auxiliary `$defs/traceReference` is not a second root record type.

## Strict bytes and acyclic construction

Pin RFC 8785 JCS, UTF-8 and SHA-256. The existing component environment uses Python `rfc8785==0.1.4`; any independent implementation must produce identical JCS bytes, not substitute ordinary `json.dumps(sort_keys=True)`. Verify the checker records its actual library version. Exact schema-file SHA-256 is a separate operation from a value's JCS digest.

1. Strictly decode UTF-8 JSON before obtaining an object model. Reject duplicate names at every depth, BOM, malformed JSON, trailing content, non-finite numbers and lone Unicode surrogates. Reject integers outside the interoperable safe range `[-9007199254740991, 9007199254740991]`; reject numeric values that the pinned RFC 8785 implementation cannot represent. Do not silently truncate or stringify numbers. JCS's prescribed number serialization is allowed; do not add Unicode, timestamp, case, ref, selector or version normalization.
2. Resolve the selected owner binding context independently of the trace. It supplies the exact expected action, authorization result/decision bundle, full rule selector and digest, intent/schema, result ID/ref/digest/schema, contract, selected action/body-schema binding and domain-payload schema binding. Self-declared trace bindings are never their own expected context. The harness receives fixed fictional expected context as separate input; it does not exercise a real independent context producer. No runtime producer of this context is supplied by this component.
3. Resolve and verify real locally pinned schema documents and every referenced schema dependency. Match exact bytes/digests, version and complete selector. Validate the chosen schema under Draft 2020-12 with an explicitly closed object contract and its complete pinned closure. No network, wildcard, fallback, boolean-true schema, unbound dynamic schema or merely plausible digest is an acceptable replacement. Unavailable, mismatched or unreviewed schemas stop integrity verification, for FAIL as well as PASS traces.
4. Finalize the foreign authorization result, rule, effect intent, proposed result and protected-effect contract under their respective owner rules. The trace carries their exact bindings. For example, PR23 resultDigest covers JCS of the whole result with no exclusions; its contractDigest removes exactly the contract's own top-level member. PR11 decisionBundleDigest retains PR11's joint projection. Do not use the trace's whole-value rule to guess any other owner's digest. Missing real foreign bytes/projection/binding remain an unavailable dependency, not a successful verification.
5. Produce the domain-owned payload against its real selected closed schema. Validate its complete payload value, then compute `domainPayload.digest = sha256: + SHA256(JCS(payload))`, excluding nothing. The payload must not depend on a future trace/receipt/consumption/attempt digest. Its owner retains all AR/PC applicability, prerequisite, verdict and truthful-execution obligations. The proposed shared payload hash convention requires the domain payload to be self-digest-free; do not apply a foreign self-digest exclusion to it.
6. Assemble and validate the closed trace value with every binding fixed. Require the resolved payload's `/overallDisposition` to equal the trace's disposition exactly. Compare each complete carried binding with its separately supplied expectation. Compare `selectedActionBodySchemaBinding` with the complete body binding selected by the resolved contract for the same action, including ref/fragment, version, file-byte digest and canonicalization. The comparison is required even if a producer honestly recomputes every affected hash. The exact implemented comparison checklist and owner gaps are below; there is no generic identity-continuity claim. The root `authorizationResult.digest` is an owner-defined record digest and is not automatically equal to `decisionBundleDigest`.
7. Compute `H = lowercase_hex(SHA256(JCS(complete trace value)))`. Excluded JSON Pointers: **none**. Construct the external reference `{ref: "urn:ofarm:protected-effect-validation-trace:sha256:" + H, digest: "sha256:" + H}`. Verify both strings against actual trace bytes. That reference carries the trace into PR40; it is not inserted into the trace. No original raw formatting claim is made for JCS-addressed values: lexical whitespace or key order can differ with the same JCS value, while exact string/array-value changes must be preserved and hashed.
8. Freeze the trace. Later consumption, attempt and receipt records may bind the finalized trace ref/digest under PR26's existing ordering. The payload is finalized before the trace; the trace before those later records. This component adds no backward digest edge, no future timestamp and no proof of commit. Changed bytes cannot reuse an existing immutable trace ID or ref/digest. That restriction is necessary for record integrity but is not permission to issue or consume a replacement PASS under a new ID for the same attempt or subject. The envelope contains no trusted attempt/subject key and has no authoritative history; it cannot establish whether such a second trace is admissible. Keep earlier FAIL evidence unchanged and retain the separate PR26 failure/admission obligations pending the B1 source assessment.

## Checks beyond JSON Schema

JSON Schema enforces the root and all common binding object members, including the required selected action/body-schema object, exact profile/canonicalization constants, selector exclusivity, digest lexical form, whole closed payload binding, fixed verdict pointer and PASS/FAIL carriage. Every reusable object definition is closed. The external reference shape is separately validateable through `$defs/traceReference`.

The component checker must separately exercise duplicate-name rejection, JCS validity/canonicalization, exact expected-binding equality including the selected body binding, selected-body equality with the resolved contract, content-digest selector agreement with the resolved rule, real local schema closure, payload schema validation, payload digest and verdict equality, external trace reference/hash equality, and local immutable-ID collision rejection. With PR40's unchanged schema it must verify both the external record binding and the trace/disposition wrapper. Each binding comparison includes the entire selected object, full selectors and exact strings, not only the hash token. The selected-body correction requires separately targeted omission/shape, expected-context drift, resolved-contract disagreement and whole-value digest controls; honest re-finalization cannot excuse a body binding that disagrees with the independent expectation or selected contract.

A schema-valid trace is **shape-valid only**. Successful envelope integrity verification means its carried bindings, available local bytes and copied verdict agree under this draft. It does not establish that the domain checks ran, that the claimed verdict is true, that trusted state is genuine, that authorization is current, or that a result was admitted/committed. Deliberately fictional closed payload/schema/contract/record examples can verify the envelope mechanism, but must be identified as TEST_ONLY and never reported as a real domain-contract pass. An unavailable foreign dependency must be reported as unavailable, not converted into a fabricated overall FAIL and not counted as verified integrity.
